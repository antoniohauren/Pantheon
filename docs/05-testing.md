# Testing and verification

## 1. Four kinds of evidence, never mixed

| Kind | What it proves | Where |
| --- | --- | --- |
| **Synthetic** | Our code meets our contract on inputs we generated | `cargo test` on Linux, Windows and macOS CI |
| **Differential** | Pantheon matches pkg-tools on the same input | Local, opt-in (`PANTHEON_PKG_TOOLS=…`) |
| **Independent reference** | A third-party implementation agrees (LibOrbisPkg, the upstream ZArchive reader, Python/OpenSSL checks) | `reference/`, pinned revisions |
| **Real target** | It works in RPCS3, shadPS4 or on a console | Manual, recorded in `docs/verification-log.md` with date, versions and outcome |

A support claim names the kind of evidence it rests on. "Works" without a log
entry means only synthetic.

## 2. Synthetic fixtures

- Generated by `cargo xtask fixtures` from code in `fixtures/`. Small outputs
  (< 1 MiB) are committed. Large ones (> 4 GiB virtual files) are generated as
  sparse files at test time.
- Only public or test keys. No game data, ever.
- Each format gets a minimal valid case, every supported variant, and a
  corruption sweep (truncate at every structural boundary, flip length fields,
  inflate counts).

## 3. Differential testing against pkg-tools

pkg-tools at `20e3c3a` is the oracle during the rewrite:

- `xtask diff <god> <input>` runs both CLIs and compares normalised JSON (parsed
  with the dev-only `serde_json` in `xtask`, P14)
  (inspect, list, trophies) or output manifests (path, size, SHA-256 for
  extract, convert, liberate, rebuild). `xtask diff hades` compares the two
  extracted trees byte for byte, which is stricter than comparing hashes.
- Private inputs stay under an ignored `pkgs/` directory. Reports print
  pass/fail and counts, **never** hashes or names of private content.
- A god reaches parity when its differential suite passes on every local fixture
  pkg-tools was verified against (README, *Verification*).

## 4. Robustness

- No panics on any input: format crates are fuzzed in two layers (D20): a
  seeded `Corruptor` harness in every `cargo test` on all three OSes, and
  cargo-fuzz targets in `fuzz/` (one per parser: SFO, XML, PS3 PKG, PS4 PKG,
  PFS/PFSC, TRP, ZAR reader, `hermes-wire`) run by a scheduled nightly-toolchain
  job and before each release. Every crash
  becomes a committed regression fixture.
- Allocation bound tests: the dev-only `pantheon-testalloc` crate (D14), a
  counting `GlobalAlloc` wrapper over `std::alloc::System`, asserts peak usage
  under the documented limit for hostile length fields. Each such test runs in
  its own test binary (`tests/alloc_*.rs`), so tests running in parallel do not
  disturb the count.

## 5. Filesystem safety suite

Runs on all three OSes: existing output, symlink/junction parents, case
collisions, reserved names, incomplete markers, injected I/O errors after N
bytes, cancellation at every phase, and source mutation detection.

## 6. GUI

Model tests cover enablement, validation and job state for every god without a
display. Toolkit smoke tests are opt-in and graphical (as in pkg-tools), one per
frontend, using synthetic fixtures.

## 7. CI gates (every change)

On Linux, Windows and macOS: `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings` (default members),
`cargo test` (default members), and `cargo xtask deps --core`.
In one Linux job with GTK installed: `cargo clippy --workspace --all-targets -- -D warnings`
and a build of the GUI and console crates. Skipped graphical and reference checks are
listed in the CI summary, not silently omitted.
